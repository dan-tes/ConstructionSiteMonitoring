# Итоговые результаты

## Что сделано

Система работает от начала до конца. Пользователь загружает план и видео
или фото с площадки. Конвейер vision → visual_phase → phase → delay
отрабатывает на реальных моделях, после чего пользователь получает фазу
стройки, прогноз отставания, текстовый отчёт, графики и выгрузку «план —
факт» в `.xlsx`. Всё поднимается одной командой (`scripts/dev_up.sh`).

| Модуль | Что сделано | Статус |
| --- | --- | --- |
| [1. План](modules/planner.md) | канонический парсер и нормализация свободных планов через LLM по словарю из 43 работ | работает, качество не измерено |
| [2. Техника](modules/vision.md) | YOLOv8m, 13 классов, дообучение в три этапа, трекинг на видео | работает, метрики есть |
| [2б. Фаза по снимку](modules/visual_phase.md) | ансамбль DINOv2 + SigLIP + zero-shot, обучен на 60 стройках | работает, метрики есть |
| [3. Фаза проекта](modules/phase.md) | модель по технике v2_ft и объединение со снимком марковской цепью по истории | работает, метрики есть |
| [4. Отставание](modules/delay.md) | Earned Schedule с поправкой на уверенность в фазе | работает, на реальных данных не проверено |
| [5–6. Отчёты](modules/reports.md) | тексты YandexGPT со ссылками только на реальные файлы | работает, качество не измерено |

## Ключевые цифры

**Определение фазы** (главная метрика): 60 таймлапсов строек, 36 тыс.
размеченных дней, проверка на стройках, которых модель не видела.

| Шаг | Точность по дням |
| --- | --- |
| константа «самая частая фаза» | 35.7% |
| модель по технике v1 (синтетика), 14 роликов | 20.9% |
| модель по технике v2_ft | 52.3% |
| только снимок (SigLIP) | 55.5% |
| техника + снимок (DINOv2) | 60.6% |
| **техника + снимок (DINOv2 + SigLIP + zero-shot)** | **66.4%** |

С допуском ±1 фаза по порядку модель по технике даёт 75%. Массовые фазы
модель узнаёт хорошо: каркас 80%, отделка 79%, земляные работы 67%,
наружные работы 61%. Редкие почти не узнаёт: кладка 5%, инженерные системы
и пусконаладка 0%.

**Детекция техники:** на MOCS val mAP50 0.78 и mAP50-95 0.60, на
дополнительных датасетах mAP50 0.81–0.95. На реальных кадрах таймлапсов F1
по наличию класса 0.55.

**Тесты:** 74 автотеста, все проходят. Плюс сквозной тест на живом стеке.
См. [testing.md](testing.md).

## Что узнали по дороге

- **Обучение на синтетике не переносится на реальные данные.** Модель v1
  на реальных таймлапсах оказалась хуже константы: 20.9% против 37%.
  Помогло обучение на выходе симулятора детектора (38.6%) и дообучение на
  реальных рядах (54.4%).
- **Один снимок без истории вводит модель в заблуждение.** Модель
  обучалась на окнах по 128 дней, а на вход ей подавали один день, и
  ответы были систематически неверными. Решение — хранить ежедневную
  историю техники по проекту.
- **Второй, независимый сигнал даёт больше, чем доработка первого.**
  Снимок сам по себе примерно равен технике (55% против 52%), но вместе
  они дают 60–66%.
- **mAP на датасете не показывает качество на реальных кадрах.** После
  дообучения метрики на датасетах выросли, а на широких кадрах таймлапсов
  детектор находит меньше, чем старый чекпоинт.

## Что осталось

- Проверить прогноз отставания и объединение фаз по истории на реальном
  проекте с серией записей и известной датой сдачи.
- Собрать данные по редким фазам: Masonry, MEP, Commissioning,
  Preconstruction.
- Вернуть детектору качество на широких ракурсах: дообучить на кадрах
  таймлапсов или взять за основу старый чекпоинт.
- Собрать размеченный набор планов для оценки модуля 1.
- Добавить разбиение площадки на зоны. Для этого нужна привязка камер к
  плану площадки.
