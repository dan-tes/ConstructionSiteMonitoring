# Тесты

Всего 74 автотеста, все проходят (прогон 28.09.2026):

| Набор | Тестов | Время |
| --- | --- | --- |
| `backend/tests/` | 45 | ~8 с |
| `services/phase/test_fusion.py` | 9 | <1 с |
| `services/delay/test_worker.py` | 20 | <1 с |

Для автотестов не нужны ни Docker, ни GPU, ни ключи YandexGPT.

## Как запускать

```bash
# backend
cd backend
uv sync --group dev
uv run pytest

# сервисы: из папки сервиса, с зависимостями из его requirements.txt
cd services/phase && python -m pytest
cd services/delay && python -m pytest
```

## Backend

Тесты работают с SQLite в памяти. Postgres не нужен, у каждого теста своя
чистая база. RabbitMQ и ML-сервисы заменены подставной функцией
`_fake_publish` из `tests/conftest.py`. Она перехватывает каждую
`*.command`, сразу формирует готовый `*.result` и передаёт его в нужный
обработчик `analysis.handle_*_result`. Так оркестрация конвейера
(`analysis.py`) проверяется целиком, но без брокера и моделей.

| Файл | Что проверяет |
| --- | --- |
| `test_auth.py` | соль стабильна и не выдаёт, существует ли пользователь; регистрация, вход, сессия, выход; валидация логина; закрытые маршруты без токена |
| `test_projects.py` | CRUD проектов и журнала, изоляция проектов между пользователями, валидация |
| `test_media.py` | загрузка, скачивание и удаление плана; канонический `.xlsx` разбирается без LLM; ошибка planner помечает план как `failed`; видео и фото проходят весь конвейер до `ready`; запись из нескольких файлов даёт один общий анализ; накопление ежедневной истории техники; текстовые отчёты попадают в запись и проект; отказ для неподходящих типов файлов; файл удаляется с диска вместе с записью |
| `test_phase_fusion.py` | `phase.command` несёт визуальную историю проекта; неудачный или молчащий `visual_phase` не блокирует запись (таймаут); фаза записи — это ответ сервиса `phase`; предупреждение об устаревшей оценке |
| `test_progress.py` | выгрузка «план — факт» с фактом и историей; закрытие проекта замораживает отчёт и запрещает изменения; оценка даты начала фазы (середина перехода, отсев кратковременных скачков с низкой уверенностью); данные для графиков с планом и без него |
| `test_report.py` | ссылки на файлы в тексте отчёта ведут только на файлы этой записи, неизвестные id отбрасываются; без клиента LLM или при его ошибке отчёт равен `None`, а исключения нет |

## Сервис phase: `test_fusion.py`

Проверяет объединение техники и снимков скрытой марковской цепью
(`fusion.py`) на синтетических временных рядах:

- фото арматуры перевешивает экскаватор, который ещё стоит на площадке;
- при обычном ходе работ модель доходит до Masonry;
- одиночный выброс назад не стирает историю, а подтверждённый откат принимается;
- фаза не «додумывается» вперёд после последнего наблюдения;
- дни, заполненные forward-fill, по умолчанию не влияют на результат;
- первому наблюдению следующей фазы модель верит;
- без наблюдений модель возвращается к последнему известному состоянию;
- вклад каждого сигнала в ответе виден отдельно.

## Сервис delay: `test_worker.py`

- `TestBaselineNotebookParity`: `forecast_delay()` даёт те же ответы, что и
  ноутбук `latency_prediction/delay_forecasting_baseline.ipynb`, на всех его
  сценариях: on_track, warning, critical, ahead, low_confidence,
  not_started, insufficient_data.
- `TestForecastDelay`: пороги статусов, сжатие прогноза при низкой
  уверенности в фазе, граничные случаи.
- `TestCompute`: переход от формата сообщения к аргументам модели,
  пересчёт долей фаз на критический путь, запасной вариант, когда дата
  начала фазы неизвестна.

## Сквозной тест на живом стеке

```bash
scripts/dev_up.sh                                     # или docker compose up -d в backend/
scripts/smoke_test_narrative_report.sh [media_file] [base_url]
```

Скрипт работает через настоящий HTTP API: регистрирует пользователя,
создаёт проект, загружает запись с видео или фото и ждёт статуса `ready`.
Весь путь vision → phase → delay → текстовый отчёт проходят реальные модели.
Скрипт завершается с ошибкой, если анализ упал или не уложился в
`POLL_TIMEOUT_S` (по умолчанию 300 с). Для текстового отчёта нужен ключ
YandexGPT.

## Что автотестами не покрыто

- Сервисы `vision`, `visual_phase` и `planner`. Их проверяет только
  сквозной тест, потому что им нужны веса моделей или ключ LLM.
- Качество моделей. Это отдельная офлайн-оценка на размеченных таймлапсах,
  см. [results.md](results.md).
- Frontend: автотестов нет, есть только `npm run lint` и сборка
  `npm run build`, которая проверяет типы.
