# Модули 5–6. Текстовые отчёты

Код: `backend/report.py`.

## Зачем

Сами по себе числа (фаза, SPI, отставание в днях) мало что говорят
прорабу и заказчику. Модуль пишет короткое пояснение человеческим языком:
что видно на площадке, как это соотносится с планом и на каком снимке это
видно.

## Как работает

- **Модуль 5, отчёт по записи.** Строится по фазе и отставанию этой записи
  и по технике, найденной на каждом её файле, а не только по общей сумме.
  Поэтому модель может сослаться на конкретный снимок: например, «на этом
  фото техники нет, что согласуется с отставанием».
- **Модуль 6, отчёт по проекту.** Использует те же факты, но описывает
  текущее состояние проекта в целом.
- Модель — YandexGPT через OpenAI-совместимый API Yandex Cloud, ответ в
  структурированном JSON.
- Модель не пишет URL сама. Ей передаётся закрытый список файлов записи,
  и сослаться она может только маркером `[[file:ID]]`. Код заменяет маркер
  на настоящую ссылку, а неизвестный id отбрасывает. Поэтому ссылка не
  может вести на файл, которого нет в записи.
- Модуль вызывается прямо внутри backend после `delay.result`. Отдельного
  сервиса и очереди у него нет.

## Качество

Количественной оценки текстов нет. Тесты проверяют главное: ссылки ведут
только на реальные файлы записи, в промпт попадают все файлы и их данные,
а при ошибке LLM отчёта просто нет, и анализ не падает.

## Ограничения

- Модуль необязательный. Без ключа `YANDEX_CLOUD_*` или при ошибке LLM
  отчёт не генерируется, но запись всё равно получает статус `ready`.
- Текст опирается только на числа конвейера. Если ошибся модуль 3, отчёт
  убедительно опишет неверную фазу.
